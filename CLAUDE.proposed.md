# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A WeChat Mini Program that renders a location-based AR experience. Users scan a QR code that carries an `organizationId`/`workspaceId`, then walk around while nearby user-generated "assets" (text bubbles, 3D models, images, audio, video, danmaku) appear in AR around them. Branded internally as "Spatial Memories". The production AR renderer is **VisionKit v2 + Three.js r186** (`miniprogram/lib/three-runtime/`, since 2026-10-09); the earlier `xr-frame` renderer survives only in the lab page `miniprogram/labs/xr-three/xr-view/` and in the upstream reference demo. Backend is the Web platform's anonymous **`/api/miniapp/*` routes**, reached only through `miniprogram/utils/backend.ts` (no Supabase, no keys in the client).

`package.json` has `esbuild` + `three@0.186.1` devDependencies and scripts: `build:xr-three-lab` (bundles Three into `lib/three-runtime/vendor/three.js` plus proxy modules for the lab), `test:xr-three-lab`, `test:ar-runtime`, and `test` (runs `scripts/test-xr-three-lab.cjs`, `test-ar-runtime.cjs`, `test-anchor-recognition.cjs`, `test-capture-motion.cjs`, `test-asset-timing.cjs` against native-API stand-ins — not a substitute for a real device). The generated bundles are committed, so WeChat DevTools needs no npm build. There is no linter. TypeScript is transpiled by the WeChat DevTools compiler plugin (`useCompilerPlugins: ["typescript"]`), not `tsc`; `tsconfig.json` exists only for editor typechecking.

## Architecture

### Page flow
`app.json` registers `pages/index/index`, `pages/ar/ar` and the subpackage `labs/xr-three` (`index`, `bridge`). `pages/logs` and `pages/upload` still exist on disk but are **not registered** (dead code).
- `pages/index` — landing / scan-entry. Resolves `CONFIG` from launch params, fetches org/workspace display names via `fetchOrganizations` / `fetchWorkspaces`, manages a **scan-history dropdown** (recently used org/workspace, persisted in Storage). `goToAR()` navigates to the AR page carrying the current config in the query.
- `pages/ar` — the AR host page. Owns location (`wx.startLocationUpdate` + `onLocationChange`, falling back to polling), compass (`wx.onCompassChange`), the GPS/匹配 mode switch, the danmaku input bar (`upload_text_asset`), and the optional shop-checkin panel (`components/shop-checkin`). Embeds the `xr-start` component as `#main-frame`, forwards GPS/compass/nav/mode into it via `selectComponent`, and listens to its `orgconfigload`, `recognitionstatus`, `recognitionframe`, `asseterror` events.
- `labs/xr-three` — validation pages: `index` is the standalone VisionKit + Three experiment, `bridge` the historical xr-frame ↔ Three bridge (`xr-view/` is the only remaining xr-frame scene). They share `lib/three-runtime`; the main package does not depend on the subpackage.

### The AR renderer: `miniprogram/lib/three-runtime/`
`ARRuntime` (`ar-runtime.js`) owns one VisionKit v2 session (`vk-session.js`: camera, metric pose, plane hitTest) and one WebGL2 canvas: a native camera YUV background pass (`vk-renderer.js`) followed by a `THREE.Scene` render in the same GL context (`renderer.resetState()` around the native pass is mandatory). `syncVKCamera` copies the VK view/projection matrices into the Three camera every frame. `resources.js` provides `loadGLTF` (GLTFLoader + a mini-program resource plugin; no Draco/meshopt, no KTX2-only textures), `loadTexture`, `disposeTree` and `ModelCache`. `text.js` lays text bubbles out into a DataTexture plane; `video.js` decodes through the native VideoDecoder into an RGBA texture (TBB alpha by default). `vendor/three.js` is the committed esbuild bundle. Frame costs are logged every 2 s as `[ThreeAR][timings]` (JS/API time only).

### The AR business component: `miniprogram/components/xr-start/`
`index.wxml` is a single `<canvas type="webgl2">` plus a status overlay. `index.js` is a WeChat `Component` whose `methods` are **composed by spreading many factory modules** (`...gps`, `...matching`, `...assetsMethods`, `...danmakuMethods`, etc.). Per-instance mutable state is not in `data` — it's assigned onto `this` via `buildInitialState()` in `attached()`. `data` only holds reactive UI flags (`arReady`, `retrievalMode`, `renderError`, `renderStatus`, `canRetry`). When adding state, extend `buildInitialState()` and clean it up in `detached()`. `ready()` creates the `ARRuntime` and two `ModelCache`s; `this.shadowRoot` is the runtime's content `Group` that every placed node is added to. Lifecycle: `handleARReady` (first valid camera frame → first-fetch gate, flush pending assets, confetti), `handleTick(dt)` (per-frame loop driven by the VK RAF), `onARState` (status/error UI), `pageLifetimes.hide/show` (stop/restart the VK session; hiding clears all assets).

Sub-modules:
- `assets/` — remote asset fetch + placement. `index.js` fetches via `backendRpc("get_nearby_assets")` and dispatches by `file_type` to `text.js` / `model.js` / `image.js` / `audio.js` / `video.js`. `queue.js` is the **generic capacity engine**; `registry.js` is the **type→descriptor table** that drives it; `huge.js` handles `is_huge` distant landmark models (`get_huge_assets`).
- `assets/scene.js` + `lib/scene-runtime/composition.js` — `scene` is an ordinary asset type; current composition JSON/resources come from `/api/miniapp/assets/scene`. Uses the same nodeList, epoch, tick/tap and disposal, with a one-scene capacity bucket. See `docs/scene-asset.md`; no workspace-mode or publication system.
- `matching/` — 匹配 mode: `capture.js` exports a JPEG from the current VK frame, `index.js` uploads it to `/api/miniapp/anchors/recognize` (`wx.uploadFile`, `RECOGNIZE_API` from `backend.ts`), locks onto the matched anchor's assets and restarts after 1.5 m net displacement; `config.js` holds intervals/limits, `log.js` the `[AnchorMatch]` logger.
- `effects/` — `danmaku.js` (flying chat-bubble animation for just-sent text), `repulsion.js` (per-frame mutual push-apart of all placed nodes), `confetti.js` (org-gated random procedural particle bursts).
- `gps.js` (location watch + first-fetch gate), `navigation.js` (stubbed — only receives state), `config.js` (`XR_CONFIG`).

### Key subsystems and their invariants

**Backend access** (`utils/backend.ts`). Everything goes through `request()` → `wx.request` to `API_BASE_URL + /api/miniapp + path`, with no auth headers. `backendRpc(name, data)` maps the former RPC names to routes (`get_nearby_assets` → `/assets/nearby`, `get_huge_assets` → `/assets/huge`, `get_shop_assets` → `/shops`, `upload_text_asset` → `/text-assets`) with unchanged parameter names and response shapes; `fetchOrganizations(ids)` / `fetchWorkspaces(ids)` are batched GETs (max 50 ids); `RECOGNIZE_API` is the recognition upload target. The server contract lives in the Web repo (`docs/miniapp-api.md`).

**Config resolution & persistence** (`utils/backend.ts`, doc: `scan-config-priority-strategy.md`). Priority: **scan params > persisted last-scan (Storage `config:scan:v1`) > `DEFAULT_CONFIG`**. `CONFIG` is a module-level singleton merged at load time; only `index.ts` calls `setConfig` in `onLoad` (the AR page must NOT, or WeChat's stale "recent" URLs would clobber a newer scan). Note the subtle Storage-spread bug guarded in `loadPersistedScanConfig`: `workspaceId` must be an explicit key or `DEFAULT_CONFIG.workspaceId` leaks in via spread. Scan history lives in `config:scan:history:v1` (`loadScanHistory` / `recordScanHistory` / `saveScanHistory`, max 20 entries).

**Capacity buckets** (`config.js` `buckets`, `assets/queue.js`, `assets/registry.js`, doc: `node-list-queue-strategy.md`). All placed nodes live in one `nodeList` array; each entry belongs to a **bucket** (`heavy`/`light`/`audio`/`transient`) declared by its type's descriptor in `registry.js`. Each bucket has independent `{ cap, evict }` and never evicts across buckets (a flood of text can't push out a model). Evict strategies: `farthest` (by XZ distance from camera — stable under head-rotation, only changes as you walk) or `fifo` (danmaku only). `minLifetimeMs` protects freshly-placed nodes; `repeatCooldownMs` (text/image) stops an evicted asset from reappearing immediately. **To add an asset type: write a placement module + add one entry to `registry.js`; the engine needs no changes.**

**Serial placement queue** (`assets/index.js` `_drainPlaceQueue`, doc: `asset-place-queue-strategy.md`). Fetched assets are placed **one at a time** with a `placeStaggerMs` gap (40 ms; models at least 120 ms) so GLB parsing / texture upload / scene insertion never pile into one frame. Async types (`model`/`video`) call `_wouldSurvive` before the expensive instantiation so they don't load only to be evicted immediately. Every async placement re-checks `_isAssetPlacementCurrent` after each `await`. (`_prefetchModelAsset` is referenced but not defined anywhere, so there is currently no parallel GLB prefetch.)

**Mode / content epochs** (`matching/index.js`). `_modeEpoch` invalidates in-flight fetches on a mode switch; `_contentEpoch` is bumped by `_clearRemoteAssets` and stamped onto every asset, so late `await`s, `_registerNode` and `displayAssets` reject stale content; `_allowedAssetIds` is the allow-list (all fetched assets in GPS mode, only the matched anchor's assets in 匹配 mode). `pauseRetrieval()` (page hide, preview) cancels requests and clears the scene; `resumeRetrieval()` refetches.

**Fetch triggering** (`index.js` `handleTick`, `config.js`, doc: `fetch-trigger-strategy.md`). Re-fetch fires on **net displacement of a fixed anchor point** (`distanceThreshold` 5 m, `fetchCooldownMs` 3000), NOT accumulated per-frame movement — this rejects VIO jitter/rotation drift. First fetch is gated on **both GPS ready AND AR ready + `firstFetchDelayMs`** (`gps.js` `_maybeStartFirstFetch`), so the camera pose has converged and assets don't spawn behind the user. **Limited reveal**: only `revealPerFetch` (10; first round `revealFirstFetch` 20) new assets are placed per round, heavy types first; the rest are dropped and reappear on later fetches for a "gradual discovery" feel.

**GLB caching** (`lib/three-runtime/resources.js` `ModelCache`; used by `assets/model.js`, `assets/huge.js`, `assets/audio.js` and `placeNode`; docs: `model-normalization-rendering.md`, `performance-optimization.md`). Each `ModelCache` (`maxCachedModelUrls` 8 for normal models, `maxCachedHugeUrls` 3 for huge ones) keys by URL, shares one `loadGLTF` promise per URL, and `acquire(url)` returns a `{ object, animations, release }` handle whose `object` is a `THREE.cloneSkinned` copy flagged `userData.sharedModel`. Entries are ref-counted; `trim()` disposes only idle (`refs === 0`) entries beyond `max`, LRU by `usedAt`, so a template with live instances is never destroyed. Instances are normalized in `instantiateModel(handle, targetSize, config)` (`Box3.setFromObject` → longest edge → `targetSize`: 1 m remote models, 0.3 m planted tree / headphone, 15 m huge) then multiplied by `asset.config.scale_multiplier`. **Always call `handle.release()` in the entry's `dispose`** (and `disposeTree(handle.object)` for abandoned loads); never dispose the shared gltf scene yourself — `disposeTree` skips `sharedModel` subtrees by default and the cache owns their release.

**Per-frame tick discipline** (`handleTick`). Everything O(N-nodes) runs each frame (billboard `lookAt`, repulsion, audio volume (throttled to 100 ms), model mixers / float animation, huge models, confetti). Hot-path rules: `entry.trs` / `billboardTrs` are the `Object3D`s cached at register time, `getCamTransform()` returns the runtime camera, and **avoid per-frame allocations** (repulsion uses flat scratch arrays; `_audioEntries` is a maintained sublist to avoid `nodeList.filter` each frame). `XR_CONFIG.debugLog` gates hot-path `console.log` — keep it `false` by default.

**Org configuration** (`index.js` `fetchOrgStyle`). The `organization.config` jsonb (`/organizations` returns only the mini-program keys) drives feature flags: `confetti_enabled`, `text_asset_miniapp_style`, `shop_checkin_enabled`, `footer_enabled`. Values are cached in Storage (`config:org:<id>:confetti:v1`, `config:org:<id>:textStyle:v1`) for a fast/offline default and re-fetched on attach. Confetti start is guarded by `_maybeStartConfetti` because two async sources race to enable it. `shop_checkin`/`footer` flags are raised to the AR page via the `orgconfigload` event; the page treats only `true` as "on", so undefined defaults to off.

### Three / VisionKit coordinate facts (docs: `visionkit-three-migration.md`; xr-frame rules in `xr-frame-coordinates.md` apply **only** to `labs/xr-three/xr-view` and `xr-frame-demo-master/`)
- **Right-handed, +Y up, camera forward = −Z.** `camera.getWorldDirection(v)` already returns the forward vector; `_calcForwardPos` derives the yaw as `atan2(fwd.z, fwd.x)` and scatters assets within ±`placeForwardArcDeg` (30°) at 1.5–5 m. `huge.js` turns a geographic bearing into a yaw with `atan2(forward.x, -forward.z)` (positive heading turns right).
- The camera pose is written by VisionKit every frame (`syncVKCamera`, `matrixAutoUpdate = false`). Never set the camera transform yourself; read `camera.position` / `matrixWorld` after the frame sync. Reticle and planting transforms come from `hitTest` matrices via `applyHitMatrix`; planting snapshots the reticle's `matrixWorld` at tap time and later loads must not move it.
- Units are metres (VK v2 metric pose); gravity is world −Y; raise objects with positive `position.y`. Billboards use `Object3D.lookAt(cameraPosition)`.
- Three uses `quaternion.set(x, y, z, w)`; the xr-frame `+Z` forward / `(0,0,1)` / `setValue` rules and scalar particle `gravity` do not apply to production code.

### Storage conventions (`.github/instructions/miniprogram-storage-persistence.instructions.md`)
Storage is for small, serializable, non-sensitive local state only. Scope keys by tenant/context: `<module>:<tenantId>:<contextId>:<name>:v<version>`. Read once at init, write on successful user action — never in high-frequency callbacks (`onLocationChange`, `onCompassChange`, per-frame tick).
