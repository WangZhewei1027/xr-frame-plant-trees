# 活动参与与 AR 展示

地图里的店铺打卡和弹幕留言由 Web 的活动投放决定。小程序从 `/api/miniapp/activities` 获取当前地图的启用活动，不再根据团队的店铺开关显示入口；同一地图的多个活动可分别选择。团队“全部地图”入口使用团队范围查询，以“活动名 · 地图名”区分同一活动的多处投放。

## 店铺打卡

一场店铺打卡活动包含多个固定地点的点，地点在 Web 的“活动内容”中维护。所有关联地图读取同一组点和参与规则，`points[].id` 与 `point_id` 都是打卡点定义 ID。卡片、导航和进度展示仍属于当前选择的地图关联，进度由 `/activity-progress` 返回的打卡点身份确定。匿名设备参与标识保存在 `activity:participant:v1`，它不是账号身份；换设备或清除小程序存储会得到新的参与标识。

打卡通过 `/activity-records` 提交，服务端确认后才更新进度和显示奖励。客户端距离提示采用 WGS84，服务端仍验证活动状态、活动参与区域和距固定地点的距离。没有坐标的点可以作为目录展示，不能导航或打卡；没有奖励图片的点仍可打卡。

旧 `checkedInShopIds` 不再读取、不用于新进度，也不会自动上传为服务端记录。旧版仅存于手机的记录无法通过服务端数据库迁移还原。

## 弹幕留言

留言选择具体活动投放后提交到 `/activity-records`，遵循活动统一的范围及字数配置，留言数据继续按地图关联隔离。发送期间禁用重复提交，成功后清空输入并播放动画；网络失败保留原文，重试使用相同的请求标识及请求体。

AR 的 `components/xr-start/activities.js` 独立拉取活动列表及各投放的可见留言，最终复用文字展示器。普通素材发现接口不承载活动数据。活动记录使用 `activity:<recordId>` 作为内部渲染身份，避免与素材投放混淆。

GPS 模式每十秒刷新一次活动及留言，即使访客停留不动也会重新检查。移出范围、暂停活动、隐藏留言或请求失败时会清理相应活动节点和待展示队列；切换识别模式、进入后台或离开页面后的迟到响应不会恢复旧内容。活动列表刷新同时更新页面入口。

## 发布与验证

此版本只使用新活动接口，不包含 `/shops`、`/text-assets` 或本地旧打卡进度的兼容路径。需要先完成 Web 仓库的存量迁移并部署新活动接口，再发布配套小程序；迁移和回滚流程以 Web 仓库的活动迁移手册为准。

`npm run test:activities` 验证活动选择、范围与字数、幂等重试、服务端打卡进度、跨投放隔离、独立留言数据源、暂停/审核清理和异步竞态。该测试已纳入 `npm test`。实际 GPS、设备存储、定位权限及地图活动的视觉展示仍需在微信开发者工具与真机验收。

## 2026-10-28 本地开发者工具验收

AR 页与店铺打卡组件的四个 WXML/WXSS 文件均通过开发者工具编译。模拟器运行时将本地请求临时转到 `127.0.0.1:3012` 的真实 Web 后端，使用隔离的 `127.0.0.1:55439/content_services` 数据库及随机测试团队；GPS 模拟为 `31.166667,121.5`。本次没有修改源代码中的后端配置，也没有生产数据库、上传或发布操作。

两场弹幕活动分别通过实际输入框输入和点击发送，真实接口各写入一条留言。店铺活动通过运行时组件方法调用提交一处打卡，确认进度为 `1/2`；切换另一活动显示 `0/2`，切回后恢复 `1/2`。数据库核对共三条 `activity_record`，类型与投放归属正确，普通 `asset` 和 `placement` 均为零。店铺打卡本次未覆盖原生按钮点击路径。

暂停四个活动投放后，真实活动接口返回 `200 []`。随后用于刷新页面的 CLI `page_action.callMethod` 出现 `this.refreshActivities is not a function` 的调用绑定错误，因此不将模拟器中的暂停入口清理记为通过；对应迟到请求和清理逻辑已有自动回归覆盖。

模拟器的 `ARReady=false`，存在 WASM 加载警告且截图为黑屏，本次不能证明 AR 画面、弹幕视觉效果或真机行为。验收后已退出 AR，恢复原扫码配置、历史、参与标识、请求函数和定位 mock，刷新回原首页；测试团队数据已删除，临时 3012 服务已停止。
